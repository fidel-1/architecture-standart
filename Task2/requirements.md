# Таблица требований FURPS+ для Банка «Стандарт»

| Категория | Требование (Арихитектурно-значимое) | Комментарий |
| :--- | :--- | :--- |
| **F**unctionality | Возможность подачи заявки на депозит через сайт и ИБ. | Ключевой функционал MVP. |
| | Интеграция с СМС-шлюзом для подтверждения операций. | Использование текущей экспертизы команды банка. |
| | Просмотр актуальных и персонализированных ставок в ИБ. | Требует создания централизованного справочника ставок. |
| **U**sability | Соответствие интерфейса системе дизайна компании. | Сохранение брендирования и привычного UX. |
| | Интуитивно понятный процесс открытия депозита в несколько шагов. | Важно для привлечения молодежной аудитории. |
| **R**eliability | Доступность сервисов 99,9% (24/7). | Требует настройки отказоустойчивости (резервный ЦОД). |
| | Шифрование трафика (TLS/SSL) для защиты данных. | Безопасность передачи ПДн на сайте и в ИБ. |
| **P**erformance | Время отклика по операциям — миллисекунды. | Оптимизация текущих медленных справочников (> 1 сек). |
| | Горизонтальное масштабирование систем (кроме АБС). | Возможность выдерживать пиковые нагрузки от маркетинга. |
| **S**upportability | Использование микросервисной архитектуры для новых функций. | Плавный уход от монолитной платформы подрядчика. |
| | Разработка архитектурной и технической документации. | Для будущего расширения и поддержки системы. |
| **+** (Constraints) | Использование баз данных Oracle и MS SQL. | Максимальное использование текущей экспертизы IT-команды. |
| | Использование Kafka для очередей сообщений. | Целевая технология для асинхронного взаимодействия. |
| | Исключение прямой работы ИБ с API АБС. | Снижение нагрузки на перегруженную БД Oracle. |
