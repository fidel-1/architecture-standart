# Таблица требований FURPS+ для Банка «Стандарт» (MVP)

Ниже представлены архитектурно-значимые требования для первого этапа запуска процесса онлайн-открытия депозитов.

| Категория | Требование (Архитектурно-значимое) | Комментарий |
| :--- | :--- | :--- |
| **F**unctionality | **Витрина ставок (Web/IB)**: Отображение актуальных условий для всех и персонализированных ставок для текущих клиентов. | Базовый инструмент привлечения и информирования. |
| | **Сбор лидов (Web)**: Форма подачи заявки для новых клиентов (ФИО, телефон) с передачей данных в CRM кол-центра. | Обеспечение процесса обзвона и предложения "особых условий". |
| | **Подача заявки (IB)**: Выбор счета/суммы и подтверждение операции СМС-кодом. | Основной функционал для действующих клиентов банка. |
| | **Централизованный реестр ставок**: Переход от XLS-файлов к единому справочнику в АБС для всех бэк-офисов. | Исключение ручного обмена файлами и ошибок в данных. |
| | **Рабочее место бэк-офиса (ABS)**: Функционал ручного подтверждения параметров заявки и открытия счета менеджером. | **MVP-ограничение**: автоматизация (STP) не предусмотрена на первом этапе. |
| | **СМС-нотификации**: Рассылка уведомлений клиенту после подтверждения ставки и открытия счета. | Информирование клиента согласно бизнес-цепочке. |
| **U**sability | **Система дизайна**: Использование брендированных элементов и цветовой схемы банка. | Сохранение целостности визуального восприятия бренда. |
| | **Скорость работы**: Быстрый отклик интерфейса (миллисекунды) при загрузке справочных данных. | Исправление текущей проблемы задержек (> 1 сек). |
| **R**eliability | **Безопасность (E2E)**: Шифрование трафика (TLS) при передаче ПДн с сайта и данных из интернет-банка. | Защита чувствительной информации и финансовых транзакций. |
| | **Доступность 99,9%**: Работа сервисов 24/7 с поддержкой переключения на резервный ЦОД. | Критическое требование для непрерывности бизнеса. |
| **P**erformance | **Горизонтальное масштабирование**: Возможность расширения фронт-систем под маркетинговые нагрузки. | Обеспечение стабильности при наплыве новых клиентов. |
| **S**upportability | **Документирование**: Описание архитектуры и API для возможности будущего расширения системы. | База для развития проекта за пределы MVP. |
| **+** (Constraints) | **Legacy-стек**: Опора на существующие БД Oracle и MS SQL. | Использование текущей экспертизы IT-команды банка. |
| | **Изоляция АБС**: Запрет на прямые API-вызовы из интернет-банка к перегруженной БД АБС. | Снижение рисков для работоспособности ядра банка. |
| | **Внутренняя разработка СМС**: Реализация логики СМС силами банка без привлечения внешнего подрядчика. | Ограничение по бюджету и срокам доработки ядра. |
| | **Законодательное ограничение (115-ФЗ)**: Обязательная очная идентификация нового клиента в офисе. | Невозможность полностью цифрового пути для новых клиентов. |
| | **Вертикальное масштабирование АБС**: Архитектурное ограничение ядра банка по производительности. | Невозможность бесконечного наращивания транзакционной нагрузки. |
